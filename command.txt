
vmm-api -- command-line client for HPE VMM Cloud

Mirrors the vmm command interface.  Instead of invoking vmm binaries
directly on a pod node, requests are sent to the capacity-aware HPE VMM Cloud
API, which selects the best pod automatically.
Authenticate with your JNPRLAB password (vmm-api auth).

VM names: bind, start, stop and unbind take a space-separated LIST of VM names
(or none = every VM in the topology). The other per-VM commands (reset,
restart, powerdown, rebuild, ping, ip, stat, serial_log, console-log ...) take
ONE VM name, or none for all where the command says so. (UX-10: this used to
claim every command took a list.)

Versions: `vmm-api --version` / `api-version` = this CLI; `api-info` = the
server; `version` = the VMM version of your TOPOLOGY. `whoami` = who the
server says your token belongs to.

-- Global flags -------------------------------------------------------------

  --dev             Use dev API (LB :8443) with separate token file
  --json            Emit raw API JSON instead of prose (read commands)
  --region <id>     Send this command to one region (also $VMM_API_REGION);
                    see `region`. VMM_API_VERBOSE=1 prints the region used.
  -u <user>         Username                    (default: the token's subject, else $USER)
  -tid <topo_id>    Topology to operate on. Omit it and commands that act on
                    one topology use yours when you have exactly one, and
                    otherwise list them and ask.

Flags may appear before or after the subcommand.

A raw token value may be supplied via $VMM_API_TOKEN (e.g. a PAT), or a token
file via $VMM_API_TOKEN_FILE.
Use 'vmm-api help <command>' for detailed help on any command.

-- Getting started -----------------------------------------------------------

launch -c <file> -g <group_id> [--wait] [--json] [--require key=val]...
    Configure, bind, and start a topology in one step.
  -c <config_file>    VMM topology config file, OR a .yml/.yaml lab
                      definition (YAML topology-as-code: name/vms/links —
                      keep it in git, launch it anywhere; goes through the
                      same validation + capacity preflight as the editor)
  -g <group_id>       Quota group for capacity allocation (default: vmm-default)
  --timeout <secs>    Abort if launch exceeds this many seconds. The topology
                      is left in place for debugging -- use vmm-api topos/unbind.
  --wait              After start, block until every VM is reachable (same poll
                      as `vmm-api wait`). On timeout the topology is left in
                      place for debugging.
  --wait-timeout <s>  Max seconds to wait for reachability (default 300).
  --wait-interval <s> Seconds between reachability polls (default 10).
  --until <state>     What --wait waits for: reachable (default), fpc-online
                      (diagnose boot probe per VM until every FPC reports
                      Online) or dataplane (FPC Online AND the PFE has exposed
                      its et-/xe-/ge- ports -- createMyVMM's fpc0 check).
                      Implies --wait.
  --console-log <dir> After the wait, save every VM's serial console as
                      <dir>/<vm>.con.log (same as `vmm-api console-log --dir`).
  --json              Emit a machine-readable result (topo_id, status, vms,
                      ips) on stdout; progress goes to stderr. Scriptable with
                      --wait for launch-and-block automation.
  --require key=val   Restrict pod selection by hardware attribute.
                      May be repeated.  Valid keys:
                      location=<site>        e.g. location=quincy
                      building=<name>        e.g. building=sabey_bldg_a
                      cpu=<codename>         e.g. cpu=cascade_lake
                      manufacturer=<vendor>  e.g. manufacturer=dell
                      domain=<lrm_domain>    e.g. domain=devtest_qnc_vmm
                      power=<1-5>            CPU performance tier (1=haswell,
                                             2=broadwell, 3=cascade_lake,
                                             4=sapphire_rapids, 5=granite_rapids).
                                             Selects that tier or newer.

quickstart -g <group_id> -vm <name>:<type> [...] [-l <a>:<b>] [-t <name>] [--require key=val]...
    Build and launch a topology by specifying VM types.
    Performs config+bind+start in one step.
  -g <group_id>       Quota group for capacity allocation (default: vmm-default)
  -vm <name>:<type>[:<image>][:<opt>=<val>]...   Add a VM.
                      A bare segment is the image file/path; the rest are
                      key=value builder options, in any order:
                        trio=<flavor>       MPC chip for slot 0 (EA/XL/XL-ETH)
                        re=<n>              RE count (dual-RE chassis)
                        slots=<A>+<B>       per-slot card flavors (slot 1..N-1); MX10004/
                                            MX10008/MX9608/PTX10004 take more of their own
                                            card: slots=YT+YT = 3 FPCs (BT on PTX10004)
                        mpc=<img>+<img>     vMX: vFPC image per MPC by slot (lts19,
                                            lts22, lts25; empty = default): mpc=+lts25
                        install=<src>,<dst> put one of YOUR files on the VM, like a
                                            config file's install line; repeatable:
                                            install=/vmm/data/user_disks/me/x.py,/var/tmp/x.py
                        version=<release>   Junos/EVO release to boot
                        chan=1              channelized ports (vScapa, vBalerion,
                                            vBrackla 10G, ...): the CSPP bundle
                                            and IF_ET_CHAN port names
                        layout=<bx0|bx1|2bx>   vBalerion: which BX slot(s) are
                                            populated (createMyVMM vbalerion-bx*)
                        base_slot=<n>       PTX-EVO chassis: slot of the first
                                            line card (templates use 1, 7, 8, 15)
                      Legacy createMyVMM --ttype names are accepted as <type>
                      and expand to the model + these options: vscapa2,
                      vscapa2fpcschan, vscapa162fpcs, voctomoreMIX2re,
                      vbalerion-2bx, vbrackla10g, ... (see `vmm-api models`).
                        setvar=<key>=<val>  per-VM setvar; REPEATABLE
                        macro=<NAME>=<val>  image-macro override; REPEATABLE
                      Example: -vm r1:vsrx:junos-vsrx3-x86-64-23.4R2-S3.10.vmdk
                      Example: -vm r1:vmx240:trio=EA:setvar=use_uefi=1 \
                                   -vm h1:ubuntu:'setvar=+qemu_args= -smp cores=2'
                      Example: -vm r1:vmx240:macro=VMX_MPC_DISK=VMPC_LTS22_IMAGE
                      Quote a segment whose value contains spaces. Values may
                      NOT contain " ' ` ; $ | & < > \ or a newline -- they reach
                      the pod's config parser AND its shell, so they are
                      rejected, never sanitized. Which keys apply to which
                      model, and which the chassis macro would clobber:
                      `vmm-api setvars [<type>]`.
  -l <a>:<b>          Private bridge link between two VMs; may be repeated
  -l <a>@<port>:<b>[@<port>]
                      ...pinned to a port: a number, or an interface name,
                      e.g. -l r1@et-1/0/0:u1 lands on FPC 1 port 0
  -t <topo_name>      Topology name (default: quickstart)
  --preview           Print the VMM config this spec compiles to and STOP --
                      nothing is reserved, bound or started. The way to see
                      what your setvar=/macro=/trio= options really emit
                      before spending a launch on them.
  --require key=val   Restrict pod selection (see launch --require above)

setvars [<vm_type>]   The per-VM setvar + macro-override catalog, grouped, with
                      help for every key (served by GET /v1/catalog/setvars --
                      never hardcoded here). With a <vm_type>, shows only what
                      that model accepts and says why anything is refused.
  --legacy            Include the legacy/deprecated keys.
  --json              The raw catalog document.

models / images       List available VM types with model, version, and image.
models --full [text]  Full catalog, human-readable: chassis (slots/RE/releases) + linecards w/ real ports.
                      --versions lists every release; a text arg filters to matching chassis/models.

-- Topology management -------------------------------------------------------

config <file> [-g <group_id>] [--require key=val]...
    Upload a topology config.  Returns a topo_id.
  -g <group_id>       Quota group for capacity allocation (default: vmm-default)
  --require key=val   Restrict pod selection (see launch --require above)

config-print [-p]     Display the current active config.
  -p                  Show the backing storage location (pod/db/table/user)
                      instead of the config contents.

validate -c <file> -g <group_id> [--require key=val]...
    Dry-run: check capacity without deploying.  Reports
    VM count, token count, and which pods have capacity.
  -c <config_file>    VMM topology config file (required)
  -g <group_id>       Quota group for capacity allocation (default: vmm-default)
  --require key=val   Filter pods by hardware attribute (see launch --require)

bind [-r vm_name ...]  Bind VMs (launch QEMU processes, paused).
    Omit vm_name to bind all; use -r for a subset.

start [-r vm_name ...] Start paused VMs.  For unbound VMs, binds then starts.

stop [-r vm_name ...]  Pause QEMU emulation.  Does not delete the QEMU process.

unbind [-r vm_name ...] Release VMs.  Does not cleanly shut down the guest OS.
  --purge-images      On a FULL unbind also delete the private images the
                      topology's spec named (your user_disks / ~/vmm-images),
                      unless another of your bound topologies still uses them.
                      createMyVMM's --r. The shared base_disks store is never touched.
                      (aliases: destroy, teardown)

export                Print the current topology's userdb as JSON. Redirect to
                      a file to save it.
  vmm-api export -tid <topo_id> > topo.json

import <file.json> -g <group_id> [-u <user>] [--ttl <duration>]
    Recreate a topology from an exported JSON file.
  -g <group_id>       Quota group for capacity allocation (default: vmm-default)
  --ttl <duration>    Optional lease duration

clone [-g <group_id>] One-shot export+import: copy the current topology's
                      config into a NEW topo_id (config stage only — bind
                      and start the copy yourself). Group defaults to the
                      source's.

relaunch -tid <topo_id> [-g <group_id>] [--ttl <duration>] [--no-start|--config-only]
    Rebuild a topology you already UNBOUND, from its stored config, keeping
    the SAME topo_id, and bring it up: config + bind + start, like launch.
    (`bind -tid <id>` alone also rebuilds it -- legacy client_config parity.)
  --no-start          rebuild and bind, leave the VMs paused
  --config-only       just place it; bind and start it yourself
    Configs are kept 60 days after teardown. The rebuild is a fresh instance:
    new VMs, no guest state from before.

                      server-side parser (unparseable pieces are warned,

configs [list]        Your saved-config library (what the editor's Save

                      -f <file> stores one; rm <name> deletes.

-- Lease (auto-unbind) -------------------------------------------------------

A bound topology gets a 30-day lease and is unbound automatically when it
lapses.  Every topology has a TOTAL LIFETIME BUDGET of 90 days, measured from
when it was placed, and you may extend as often as you like inside it -- there
is no separate limit on the NUMBER of extensions.  You are emailed a warning
7 days and again 24 hours before the unbind.  Tooling topologies are exempt.

An auto-teardown TTL (--ttl at launch) is extendable the same way: `extend`
moves whichever clock actually ends the topology, so a `--ttl 4h` lab can be
pushed out when you need longer instead of dying at 4h.

lease                 Show lease status: expiry, the effective end (the earlier
                      of lease and TTL), and how much of the 90-day budget is
                      left for the current topology.

lease schedule <when> Schedule the auto-unbind EARLIER than the lease expiry
                      (shorten only — extend is `vmm-api extend`). <when> is
                      an ISO datetime or relative: +30m, +4h, +2d.

extend [--for <duration>]
                      Push the end out, within the 90-day budget.  Moves the
                      TTL if a TTL is what ends the topology, otherwise the
                      lease.  --for takes the same forms as --ttl (30m, 2h,
                      4h30m, 7d); omit it to repeat what this topology already
                      had -- its own TTL, or the group's lease period.

  vmm-api lease  -tid abcdef
  vmm-api lease schedule +4h -tid abcdef
  vmm-api extend -tid abcdef              # again by its own TTL / lease period
  vmm-api extend --for 2d -tid abcdef     # ...or by an amount you choose

-- Config lifecycle (running-config history) ---------------------------------

Versioned `show configuration | display set` snapshots pulled off the live
Junos REs of a running topology. The FIRST snapshot of a node is its drift
baseline — capture right after the lab settles, then `drift` answers "what
changed since launch". Snapshots survive teardown (query by -tid).

cfg capture [vm ...] [--source <label>]
                      Snapshot running configs (no vm = every Junos RE).
                      Identical text dedups — re-capturing an unchanged
                      node adds no history.

cfg history [vm]      List snapshots (seq, source, size, who, when).

cfg show <vm> [seq]   Print one snapshot's config text (default: latest).

cfg diff <vm> [--from <seq>] [--to <seq> | --live]
                      Unified diff between snapshots (default: baseline ->
                      latest). --live compares against a fresh capture off
                      the running node without storing it.


cfg apply <vm> [--seq N] [-f <file>] [--from-tid <tid> [--from-vm <vm>]]
          [--from-seq N] [--no-strip] [--dry-run] [--yes]
                      Load a stored config back onto a live RE and commit.
                      Sources, pick one: --seq (this topology's own history,
                      default latest), --from-tid/--from-vm (another
                      topology's -- it may already be torn down), or -f a
                      file of `display set` lines (what `cfg show` prints).

                      This is a MERGE (`load set`): it adds and changes,
                      it never removes.  A statement you deleted on the box
                      comes back; a statement you added since the snapshot
                      STAYS.  It is not a revert.

                      Node-identity lines -- host-name, root-authentication,
                      licences and the management interface (fxp0, mgmt-N,
                      reN:mgmt-N) -- are dropped by default so a config from
                      one node cannot lock you out of another.  --no-strip
                      sends the file verbatim.  --dry-run prints exactly what
                      would be loaded and touches nothing.

  vmm-api cfg capture -tid abcdef                    # snapshot the lab
  vmm-api cfg show r1 -tid abcdef > r1.set           # keep it as a file
  vmm-api cfg apply r1 -f r1.set -tid 123456 --yes   # ...onto a fresh lab
  vmm-api cfg apply r1 --from-tid abcdef -tid 123456 --dry-run
drift [--latest]      Live config vs baseline for every captured node —
                      DRIFTED/clean per node with +/- line counts. --latest
                      compares against the newest snapshot instead.

  vmm-api cfg capture                      # after the lab settles = baseline
  vmm-api drift                            # ...days later: what changed?
  vmm-api cfg diff r1 --live               # the actual lines, one node

-- Backups: save a lab, launch it again ---------------------------------------

A backup is the lab's design + every device's config (without the pod's own
management block), so it launches on any pod, in either region. Disk images
are named, not copied.

backup save [-tid <id>] [--no-capture]
                      Save it as a .tgz in YOUR user_disks (vmm-backups/).
backup ls             Your backup files.
backup restore <file.tgz> [--name <n>] [--no-launch]
                      Launch a lab from one.  backup rm <file.tgz> deletes.
git remote set|show|test|rm, git backup, git restore
                      The same, to and from your own git server
                      (`vmm-api git help`; user guide section 10).

  vmm-api backup save -tid abcdef          # -> vmm-backups/mylab-20260925T101500Z.tgz
  vmm-api backup restore mylab-20260925T101500Z.tgz --name mylab-copy

-- Lab validation (assertions) -----------------------------------------------

A lab YAML may declare a validate: block — assertions that make the lab a
testable artifact. Stored at launch; `verify` re-runs them any time:

  validate:
    - ping: {from: r1, to: r2}                     # to: VM name or IP
    - interfaces: {vm: r1, up: [ge-0/0/0]}         # admin+link up/up
    - bgp:  {vm: r1, established: 2}               # or peers: [10.0.0.2]
    - ospf: {vm: r1, full: 1}                      # or neighbors: [...]
    - command: {vm: r1, run: "cli -c 'show version'", expect: "23.4R2"}

verify                Run the stored checks; PASS/FAIL per check, exit 1 on
                      any failure (CI-friendly).
verify -f lab.yml     Run a file's validate: block instead ( --save stores
                      it on the topology without running).
verify --show         Print the stored checks.    --clear  removes them.

-- Partial bind / unbind ----------------------------------------------------

-r binds or unbinds only the named VMs.  Topology state is preserved until
  all VMs are unbound.  First partial bind uses the config-time reservation;
  later binds re-check live capacity.

  vmm-api bind   -tid abcdef -r RE PFE     # bind two VMs
  vmm-api unbind -tid abcdef -r RE         # unbind one VM
  vmm-api bind   -tid abcdef -r PFE2 PFE3  # bind remaining VMs

capacity [-g <group>] Token capacity per quota group: allotted, used, free,
                      %full, and the largest VM that still fits.

telemetry -g <group>  Capacity telemetry -- the tooling BACK-OFF contract.
                      Honor `accepting` (false = don't submit) and
                      `retry_after_s` (when to re-poll). Reports total/used/
                      reserved/free tokens, the largest single topology that
                      fits RIGHT NOW (max per-pod free -- a topology lands on
                      ONE pod), the largest single VM (per-vhost bound), when
                      capacity next frees (lease/TTL/reservation expiry),
                      recent churn, and YOUR own open footprint. Cheap and
                      DB-only server-side: poll freely. The same payload is
                      attached to capacity-503 launch rejections (`telemetry`
                      body key + Retry-After header).
  --tokens <n>        Preflight: would a topology of n tokens fit?
  --max-vm <n>        ...whose largest single VM is n tokens (with --tokens).
  --plain             Script-friendly key=value lines (stable keys, no jq
                      needed; eval-able in shell). For raw JSON use --json.

capture <vm> [opts]   Bounded packet capture on a VM interface, saved as pcap.
                      Works on management AND private/VDE (data-plane) links.
  --iface <name|n>    Interface NAME (em0, ge-0/0/0) or index (default 0).
                      See the interface names in: vmm-api args <vm>
  --filter <bpf>      pcap/BPF filter, e.g. 'tcp port 179', 'host 10.0.0.1',
                      'udp and not port 53'. Quote it (contains spaces).
  --seconds <n>       Capture window (default 30, max 300; also packet-capped).
  -o <file>           Output file (default <topo>-<vm>-<iface>.pcap).
  --stream            LIVE stream pcap bytes to stdout as packets arrive
                      (window default/max 300s) — pipe into Wireshark:
                        vmm-api capture r1 --stream | wireshark -k -i -
                      Status goes to stderr; -o writes to a file instead.
  vmm-api capture r1 --iface ge-0/0/0 --filter 'tcp port 179' -tid <topo_id>

link <vm> up|down     Bring one VM interface's virtual cable admin up/down
                      (qemu set_link on the netdev — works on management AND
                      private/VDE data-plane links; the guest sees real
                      carrier loss). A VM restart brings links back UP.
  --iface <name|n>    Interface NAME (ge-0/0/0, em0) or index (default 0).
  --persist           down only: KEEP the link down across VM start/restart/
                      rebuild (re-applied automatically once the VM's monitor
                      answers; shown as persistent in --list).
  --list              List recorded admin-down links, live-verified (also
                      the default with no VM given).
  vmm-api link r1 down --iface ge-0/0/0 --persist -tid <topo_id>

diagnostics [-o F]   Download ALL logs + diagnosis bundles for the topology
                      as a .tar.gz (works AFTER teardown too) -- hand this to
                      engineering / VMM Cloud admins for deep debugging.
link-test <a> <b>     Configure a /30 on each end's revenue interface and send
                      traffic across the link between VMs <a> and <b>.
  --mode <m>          ping (default; rich ICMP stats) | tcp | udp | iperf
                      (throughput — iperf3 if present, else nc). tcp/udp/iperf
                      need linux/bsd endpoints; ping works on junos too.
  --count <n>         ping echo count (default 10, max 100).
  --port <n>          tcp/udp/iperf port (default 5201).
  --seconds <n>       iperf duration (default 5, max 30).
  --addr-a/-b <cidr>  override the /30 (default 10.99.254.1|2/30).
  --iface-a/-b <if>   pick a specific revenue interface (default: first found).
  vmm-api link-test r1 r2 --mode iperf --seconds 10 -tid <topo_id>

webhook [list|add|test|rm]
                      Your topology-event webhooks. The API has had these
                      since they shipped; there was no CLI, so registering one
                      meant hand-rolling curl with a bearer token on the argv.
  vmm-api webhook list                      # + the subscribable event names
  vmm-api webhook add https://host/hook --event lease_warning
  vmm-api webhook test 3                    # send a signed sample delivery
  vmm-api webhook rm 3
                      add with no --event subscribes to ALL events. The
                      signing secret is returned ONCE, at creation.

notify [list|seen|prefs]
                      Your notification bell, on the command line.
  vmm-api notify list [--all]   # --all also shows MUTED events
  vmm-api notify seen           # mark everything read

-- Authentication -----------------------------------------------------------

auth                  Authenticate and cache a token (8h TTL).
    Prompts for JNPRLAB password unless $VMM_API_PASSWORD is set.

auth --email <you@hpe.com> [--code <6 digits>]
    External (HPE) sign-in: no directory account needed. Emails you a
    verification code; entering it signs you in for 30 days AND enrolls this
    machine (a local device key silently re-auths afterwards). Running any
    command with -u you@hpe.com starts the same flow automatically.

auth status           What credential this CLI would send (kind, subject,
                      expiry, file) and which region/endpoint it talks to.

auth clear [--keep-enrollment]
    Forget the cached token AND this machine's external (HPE) device
    enrollment, so the next command authenticates from scratch. Clearing the
    token alone is NOT enough to change identity: an enrollment silently
    re-mints a token for the external identity once the cached one expires.
    --keep-enrollment drops only the token.

auth --tooling [--account <acct> --key <privkey>]
                      Machine identity: sign a 120s assertion with the account's
                      PRIVATE key and exchange it for a token. Defaults come from
                      $VMM_API_TOOLING_ACCOUNT / $VMM_API_TOOLING_KEY. Never uses
                      a password, and never rides a human's token.

revoke                Revoke the cached SESSION token server-side and remove
                      it locally. Refuses a personal access token -- those
                      are revoked with `pat revoke <id>`.

refresh               Extend the current token for another 8 hours.

pat create --name N [--days D] [--scope read-only,no-admin] [--out FILE]
                      Mint a personal access token for automation. Scopes only
                      RESTRICT it: read-only = GET/HEAD only (any write 403s);
                      no-admin = blocks admin endpoints even for an admin owner.
                      The secret is printed ONCE -- store it immediately, or
                      give --out FILE to have it written to a new mode-600
                      file instead of the screen (then point
                      VMM_API_TOKEN_FILE at that file).
pat list              List your active personal access tokens.
pat revoke <id>       Revoke one of your personal access tokens.

api-version           Print the vmm-api CLI version and the build fingerprint of
                      the script that is actually running.
api-info              Print the server's API/app version (JSON).

-- Regions & test runner ----------------------------------------------------

region [show | list | set <id> | reset | probe]
                      Home region this CLI talks to. `show` (default) prints the
                      cached choice (~/.vmm-api-region, 7 days; a CHANGE of home
                      region is announced on stderr, never silent); `list` the
                      region directory (id, endpoint, active); `set <id>` pins it;
                      `reset` clears the cache; `probe` re-selects by latency now.
                      Per command: --region <id> or $VMM_API_REGION; $VMM_API_URL
                      pins an endpoint outright. VMM_API_VERBOSE=1 prints the
                      region on every call; `auth status` shows it too.

tests [list | run <name> [--yes] | status [job] | logs <job>]
                      The runner's test suites (test-admins only). `list` (default)
                      shows every registered suite with its destructive flag.
                      `run <name>` launches one: DESTRUCTIVE suites (the integration
                      suites, failover drills, load-fill, ...) cause real production
                      impact and ask for confirmation -- --yes is required when
                      headless. `status [job]` shows one job or the recent-jobs
                      table; `logs <job>` a job's log. Needs a session token (the
                      runner does not accept PATs).
